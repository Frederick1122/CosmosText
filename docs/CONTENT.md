# Контент: форматы данных

Весь игровой контент лежит в `data/` в JSON (UTF-8). Код менять не нужно, если не добавляется новый *тип* эффекта, условия, характеристики или спецдействия (см. [DEVELOPMENT.md](DEVELOPMENT.md#новый-тип-эффекта-или-условия)).

**После каждой правки запускайте валидатор:**

```bash
python tools/validate_content.py
```

Код возврата `0` — ошибок нет, `1` — есть ошибки. Предупреждения (`!`) сборку не ломают, но их стоит прочитать.

## Модель контента

```
сектор (sectors/*.json)          карта: палубы, узлы, лифты
└─ узел с location_id           точка на карте
   └─ локация (locations/*.json) модуль: описание + события
      └─ событие                 авто или ручное, разовое или повторяемое
         ├─ ситуация (situations/*.json)  текст + варианты выбора
         └─ или мгновенно: text + effects

персонаж
├─ сумка          предметы (items.json), слоты с учётом рюкзака
├─ снаряжение     5 слотов: шлем, тело, руки, ноги, спина (items.json → equip_slot, stats)
├─ навыки         skills.json, прокачка за очки навыков
└─ крафт          recipes.json

цели (quests.json)               мысли героя + цели с шагами, условия — обычные requires
```

- **Локация (модуль)** — место, куда игрок попадает по клику на узел карты. В неё можно возвращаться сколько угодно раз, в том числе в пройденные (`cleared`) и опасные (`dangerous`) узлы.
- **Экран модуля** — общий текстовый буфер: либо заголовок и описание текущей локации, либо текст активного события с репликами и последствиями. При старте события описание локации очищается; после «Продолжить» событие очищается и возвращается актуальное описание модуля. Новые записи плавно печатаются сверху вниз со скоростью из настроек; звук получения предмета или патронов звучит, когда появляется соответствующая строка `[+N …]`. Под текстом — раздел «Действия» (кнопка «🔍 Исследовать отсек» и ручные события, кроме ещё не найденных скрытых — см. [«Исследование»](#исследование--explore_poolsjson)), «База» (у модуля-базы) и «Склад»/«Здесь лежит». Предметы используются только в экране персонажа или в бою.
- **Выход из модуля** — маршрут по карте: кнопка «Карта» в HUD открывает карту поверх модуля, игрок выходит, когда тронется в путь. Отдельной кнопки «Выйти на карту» нет. Завершающие варианты ситуаций (уводят на карту, заканчивают событие или забег) выделены янтарным цветом.
- **Журнал** (кнопка в HUD, она же закрывает его) — вкладки «🎯 Цели», «📜 Хроника», «🗄️ Архив» и «📚 Справочник». Справочник делится на «Места», «Люди», «Корабли» и «Термины»; статья открывается при первом упоминании понятия, а само понятие после этого подсвечивается в текстах.
- **Экран персонажа** открывается кнопкой «Персонаж» в HUD (кроме боя и экрана смерти). Подробнее — в разделе [«Экран персонажа»](#экран-персонажа).

## config.json

Стартовые параметры забега и награды опытом.

| Поле | Тип | Назначение |
|---|---|---|
| `start_sector_id` | string | Сектор, который загружается при новой игре |
| `opening_situation_id` | string | Необязательная ситуация до входа в хаб. Сейчас пусто: вступление реализовано автособытиями локации `hub` |
| `inventory_slots` | int | Базовое число слотов сумки (без рюкзака) |
| `start_hp` | int | Базовое максимальное HP (без бонусов) |
| `start_o2` | number | Стартовый запас кислорода в единицах (HUD показывает число) |
| `start_ammo` | int | Стартовые патроны. При `0` бой всегда ближний |
| `start_equipment` | object | Стартовое снаряжение `{ "слот": "id предмета" }`. Предмет должен надеваться в этот слот |
| `start_skill_points` | int | Очки навыков в начале забега |
| `o2_costs` | object | Цена действий в единицах кислорода: `move` (переход в модуль), `elevator` (лифт), `action` (ручное событие), `explore_tick` (один такт исследования), `choice` (вариант в ситуации), `combat_turn` (ход в бою). Пропущенные ключи берутся из `ResourceSystem.DEFAULT_O2_COSTS` |
| `o2_unsealed_multiplier` | number ≥ 1 | Во сколько раз дороже действия в узле без давления (`sealed: false`) |
| `xp` | object | Опыт и уровни (неотрицательные целые): `explore` (первый вход в модуль, кроме базы), `craft` (созданный предмет), `lore` (запись `unlock_lore`, один раз за забег), `kill` (победа, если у врага нет своего `xp`), `level_base` и `level_step` (до следующего уровня нужно `level_base + level_step × (уровень − 1)`), `skill_points_per_level` (очки навыков за уровень). Пропущенные ключи берутся из `ProgressionSystem.DEFAULT_CONFIG`; сейчас `10 / 10 / 15 / 20`, `50`, `25`, `1` |
| `needs` | object | Дни, силы и голод (неотрицательные числа; пропущенные ключи — из `NeedsSystem.DEFAULT_CONFIG`): `max_energy` (100) и `max_hunger` (100) — больше нуля; `energy_costs` и `hunger_costs` относятся к действиям `move`, `elevator`, `action`, `choice`, `combat_turn`; всё исследование считается одним `action`, а не каждым `explore_tick`. Остальные поля задают пороги усталости/голода, урон от голода, сон и обморок |

Кислород по таймеру не уходит: он тратится только на перечисленные действия и на эффекты `o2_delta`; в модуле с `breathable: true` действия кислорода не стоят. Те же действия тратят силы и копят голод (`needs`), где бы игрок ни был. Использование предметов вне боя, подбор вещей с пола и крафт бесплатны.

Новая игра загружает сектор и входит в локацию хаба (`hub_node`), если `opening_situation_id` пуст.

## Локации — `locations/<id>.json`

Одна локация на файл. Имя файла ни на что не влияет, значение имеет поле `id`, на которое ссылается `location_id` узла карты.

```json
{
  "id": "cargo_bay",
  "title": "Грузовой отсек",
  "image": "cargo_drone",
  "description": "Базовое описание модуля.",
  "descriptions": [
    { "requires": [ { "type": "flag", "flag": "drone_cargo_down" } ],
      "text": "Описание после того, как дрон уничтожен.",
      "image": "cargo_drone_down" }
  ],
  "events": [ ]
}
```

| Поле | Назначение |
|---|---|
| `id` | Уникальный id локации |
| `title` | Заголовок экрана. Если не задан, берётся `title` узла карты |
| `description` | Базовое описание модуля |
| `descriptions` | Необязательные варианты описания: берётся первый вариант, чьи `requires` выполнены, иначе `description`. Поле `image` варианта (необязательное) заменяет картинку модуля, пока вариант активен: так отсек после боя выглядит иначе |
| `events` | Массив событий (см. ниже) |
| `image` | Иллюстрация модуля: имя файла без расширения (`assets/art/scenes/<image>.png`) |
| `base` | `true` — модуль-база: чекпойнт при входе и раздел «База» («🛏️ Закончить день — сон и сохранение», верстак, склад). Сейчас — `hub` и `crew_quarters` |
| `breathable` | `true` — в модуле можно дышать: действия внутри (выборы, ручные события, исследование, ходы боя, обморок) кислорода не стоят. Базы помечены так же |
| `explore` | Исследование модуля: `{ "pool": "<id пула из explore_pools.json>", "rolls": <int ≥ 0>, "duration": [<min>, <max>] }`. `rolls` — число случайных находок до бонуса навыка «Поиск»; `duration` — включительные границы числа полусекундных тактов, оба значения положительные и `min ≤ max`. См. [«Исследование»](#исследование--explore_poolsjson) |

### Событие

```json
{
  "id": "force_shuttle_airlock",
  "start": "manual",
  "label": "Вскрыть шлюз к шаттлу обломком трубы",
  "repeatable": false,
  "triggers": [ { "type": "has_item", "item": "pipe_scrap" } ],
  "text": "Шлюз со скрежетом отходит.",
  "sound": "shuttle_door",
  "effects": [ { "type": "open_map_node", "node": "alien_shuttle" } ],
  "situation": ""
}
```

| Поле | По умолчанию | Назначение |
|---|---|---|
| `id` | — | Уникален в пределах локации |
| `start` | — (обязательно) | `"auto"` — стартует само; `"manual"` — пункт меню модуля, запускает игрок |
| `label` | — | Текст пункта меню. Обязателен для `manual` |
| `repeatable` | `false` | `false` — исчезает после успешного завершения, `true` — доступность определяют только `triggers` |
| `triggers` | `[]` | Условия, при которых событие доступно (формат — «Условия» ниже). Пустой массив — всегда |
| `effects` | `[]` | Эффекты, применяемые при запуске |
| `text` | `""` | Сообщение на экране модуля после запуска (для мгновенных событий) |
| `situation` | `""` | id ситуации, которая откроется. Если пусто, событие мгновенное |
| `image` | `""` | Имя файла иллюстрации без расширения (`assets/art/scenes/<image>.png`). Заменяет иллюстрацию модуля на время текущего контекста |
| `sound` | `""` | Имя WAV без расширения (`assets/sounds/<sound>.wav`). Звук проигрывается при появлении текстовой записи события в ленте |
| `clear_image` | `false` | `true` — не показывать иллюстрацию модуля на протяжении события и связанной цепочки ситуаций. Должно быть булевым |
| `lock` | — | Замок ящика: `{ "key": "<id замка>", "consume": true, "text": "..." }`. Событие видно в меню, но запускается только с подходящим ключом (см. «Ключи и замки») |
| `discover` | `false` | Только для `manual`: `true` — скрытое событие, его нет в меню и запустить его нельзя, пока игрок не найдёт его исследованием модуля |
| `found` | `""` | Текст в ленте, когда скрытое событие найдено (под ним — «[Найдено: <label>]») |

У события должно быть хотя бы одно из `situation`, `text` или `effects`.

### Как работают события

**Порядок запуска.** Сообщение `text` (с `image` и `sound`) → эффекты → ситуация `situation`. Если эффект начал бой или убил игрока, до ситуации дело не доходит.

Если у события и текущей ситуации нет своей `image`, сверху остаётся
иллюстрация модуля. Картинка события или ситуации имеет приоритет. Убрать фон
можно только явно через `clear_image: true` у события.

**Автособытия (`auto`)** проверяются по порядку массива:
- при входе в модуль с карты;
- при каждом возврате на экран модуля: после ситуации с `next: ""`, после победы в бою, после ручного события, после использования предмета, после закрытия экрана персонажа.

Запускается первое подходящее. Если оно мгновенное, сразу проверяется следующее, поэтому несколько автособытий могут отработать подряд. Ограничения:
- каждое автособытие срабатывает **не чаще одного раза за визит**;
- разовое — пока не завершено, затем исчезает на весь забег.

**Ручные события (`manual`)** видны кнопками в разделе «Действия», пока выполняются их `triggers`, — кроме скрытых (`discover: true`): они появляются только после того, как их найдёт «Исследовать отсек». Разовое исчезает после успешного завершения, повторяемое остаётся, пока его не скроют условия.

**Момент завершения.** Мгновенное событие без ситуации завершается сразу после `effects`. Событие с ситуацией завершается после «Продолжить» у терминального варианта; вариант с `completes_event: false` считается отказом и оставляет событие доступным. Для боя событие завершается после победы, но не после побега.

**Состояние событий** (сколько раз завершено) и число визитов в каждый модуль хранятся в `run.json`, сбрасываются при новой игре и восстанавливаются при откате к чекпойнту.

**Хаб.** Когда показывается экран модуля хаба, записывается чекпойнт.

## Эффекты

Эффекты используются:
- в массивах: `events[].effects`, `situations[].options[].effects`, `items[].interactions[].effects`;
- в одиночном объекте: `items[].use_effect`.

Применяет их `EffectResolver.apply_effect`. Изменения ресурсов и предметов сами попадают в ленту модуля строкой в квадратных скобках: `[−5 HP]`, `[+90 O2]`, `[−40 голода]`, `[+2 Патроны]`, `[+1 Аптечка]`, `[−1 Ключ-карта пилота]` (прибыль — зелёным, убыль — красным; у голода наоборот — убыль зелёная). Писать это в `text` / `result` не нужно. В ситуации строки встают под текстом `result`.

| `type` | Поля | Действие |
|---|---|---|
| `hp_delta` | `value: int` | Изменить HP (с ограничением `0..max_hp`). При 0 — смерть. В ленте — фактическое изменение: лечение при полном HP строки не даёт |
| `o2_delta` | `value: number` | Изменить запас кислорода (в тех же единицах, что `start_o2`). При 0 — смерть |
| `hunger_delta` | `value: number` | Изменить голод (с ограничением `0..max_hunger`); отрицательное — поесть. В ленте — фактическое изменение `[−40 голода]`, при еде звучит `heal` |
| `ammo_delta` | `value: int` | Изменить патроны (не ниже 0) |
| `item_add` | `item: id`, `count` (по умолчанию 1) | Добавить предметы в сумку. То, что не влезло, остаётся лежать на полу текущего модуля (с отдельным сообщением) |
| `item_remove` | `item: id`, `count` (по умолчанию 1) | Убрать предметы: сначала из сумки, затем надетый экземпляр |
| `flag_set` | `flag: string`, `value` (по умолчанию `true`) | Установить флаг забега. Флаги сбрасываются при новой игре |
| `unlock_lore` | `id: id лора` | Открыть фрагмент в Журнале. Первое прочтение фрагмента за забег даёт опыт `config.xp.lore` (`[+15 опыта]`); архив переживает смерть, а награда — нет: в новом забеге запись снова принесёт опыт |
| `reveal_map` | — | Убрать туман войны с карты текущего сектора на палубах, где игрок уже был (другие палубы откроются, когда он туда доедет) |
| `open_map_node` | `node: id узла` | Перевести узел в `available`, добавить `[Открыта новая локация "Название"]` и на 5 секунд показать пульсирующую карточку «Увидеть на карте». Кнопка открывает нужную палубу, фокусирует и пульсирует узлом до 5 секунд или до нажатия |
| `lock_map_node` | `node: id узла`, `state` (по умолчанию `"dangerous"`) | Выставить узлу произвольное состояние, несмотря на название |
| `skill_points_add` | `value: int` (по умолчанию 1) | Выдать очки навыков |
| `start_combat` | `enemy`, `clear_node` (опц.), `on_win` (опц.), `on_flee` (опц.) | Начать бой. `on_win` и `on_flee` — массивы эффектов на исход. `clear_node` станет `cleared` (победа) или `dangerous` (побег) |
| `end_run` | `ending: id из endings.json` | Победно завершить забег: экран «Забег завершён» с текстом финала. `run.json` и чекпойнт удаляются, итог пишется в хронику (meta) |

## Условия (`requires` / `triggers`)

Условия используются:
- в `triggers` событий;
- в `requires` вариантов описания;
- в опциях ситуаций;
- во взаимодействиях предметов;
- в рецептах;
- в спецдействиях врагов.

Все условия массива должны выполняться одновременно (логическое И).

| `type` | Поля | Истинно, если |
|---|---|---|
| `has_item` | `item: id`, `value` (по умолчанию `true`) | Предмет есть в сумке **или надет**; `value: false` — предмета нет нигде |
| `flag` | `flag`, `value` (по умолчанию `true`) | Флаг равен `value`. Неустановленный флаг считается `false` |
| `stat_gte` | `stat` (`hp`, `o2` или `ammo`), `value` | Показатель `>= value` |
| `skill_gte` | `skill: id навыка`, `value: int` | Уровень навыка `>= value` |
| `in_location` | `location: id локации` | Игрок сейчас в этом модуле (например, крафт только у верстака) |
| `event_done` | `event`, `value` (по умолчанию `true`) | Событие успешно завершено (или ещё нет при `false`). `event` — `"локация/событие"` или короткий id события текущей локации |
| `visits_gte` | `value: int` | Число визитов в текущую локацию `>= value`. Текущий визит учитывается: первый визит — это 1 |
| `visits_lte` | `value: int` | Число визитов `<= value`. `visits_lte: 1` — только первый визит |
| `has_key` | `lock: id замка`, `value` (по умолчанию `true`) | В сумке или снаряжении есть предмет с этим замком в `unlocks` |

Вне файла локации (в ситуациях, предметах, рецептах, у врагов) `event_done` требует полного id `"локация/событие"`.

Неизвестный тип условия движок считает **выполненным** (с предупреждением в лог), а валидатор выдаёт предупреждение.

## Ситуации — `situations/<id>.json`

Ситуация — текст и варианты выбора. Обычно её открывает событие локации.

```json
{
  "id": "sit_1_3_drone",
  "image": "cargo_drone",
  "text": "Текст ситуации. Поддерживаются переводы строк \n.",
  "options": [
    {
      "id": "A",
      "label": "Текст кнопки",
      "completes_event": false,
      "result": "Что произошло после выбора: игрок читает это перед кнопкой «Продолжить».",
      "requires": [ { "type": "has_item", "item": "broken_datapad" } ],
      "effects": [ { "type": "o2_delta", "value": -30 } ],
      "next": ""
    }
  ]
}
```

Значения `next`:
- `""` — вернуться на экран текущей локации (с проверкой автособытий). Если игрок не в локации — на карту.
- `"<situation_id>"` — сразу открыть следующую ситуацию.
- `"map:<sector_id>"` — покинуть локацию и перейти на карту сектора. При этом записывается **чекпойнт**. Если это текущий сектор, это отступление: игрок не остаётся в отсеке, а возвращается в узел карты, откуда пришёл. Другой сектор загружается, игрок стоит в его хабе.

С эффектом `start_combat` экран переключается на бой. После победы игрок возвращается в локацию. После побега — на карту: если бой перехватил его посреди маршрута, путь продолжается за врага, иначе игрок отходит в предыдущий узел.

Необязательное поле `image` — имя файла иллюстрации без расширения (`assets/art/scenes/<image>.png`): картинка показывается над текстом ситуации.

Прочие правила:
- **Поле `result` обязательно у каждого варианта.** Ситуация не обрывается на выборе: в ленту уходит реплика игрока, затем применяются `effects`, затем показывается `result` и кнопка «Продолжить». Только после неё срабатывает `next`. Исключения — смерть и `start_combat`: там экран переключается сразу. Цифры в `result` писать не нужно, изменения HP/O2/патронов видно в HUD.
- `completes_event` у варианта по умолчанию `true`. Для отказа или решения «вернуться позже» задайте `false`: разовое событие не помечается выполненным и остаётся доступным.
- Если все опции скрыты условиями, UI покажет кнопку «Продолжить» — она работает как `next: ""`.
- Поля `requires` у самой ситуации **нет**: движок его не применяет, валидатор считает ошибкой. Условия задаются у вариантов (`options[].requires`) или у события локации (`events[].triggers`).

## Предметы — `items.json`

Объект, где ключ — id предмета.

```json
"pipe_scrap": {
  "name": "Обломок трубы",
  "category": "weapon",
  "slot_cost": 1,
  "stackable": false,
  "equip_slot": "arms",
  "stats": { "melee_damage": 6 },
  "description": "Согнутый кусок трубы.",
  "interactions": []
}
```

| Поле | Назначение |
|---|---|
| `name` | Отображаемое имя |
| `category` | `quest`, `key`, `consumable`, `weapon`, `armor`, `gear` или `component` — подпись в UI. Логика завязана на три категории: `consumable` удаляется при использовании и получает кнопку в бою; `quest` и `key` — информационные предметы: их нельзя выбросить, и они не занимают место в сумке |
| `slot_cost` | Сколько слотов сумки занимает. У `quest` и `key` — обязательно `0` (иначе ошибка валидатора): записи и ключи места не занимают и при переполнении не вываливаются на пол |
| `stackable` | Стакается в один слот без ограничения количества. Надеваемые предметы стакаться не должны |
| `description` | Описание во вкладке «Предметы» |
| `use_effect` | Один эффект при использовании: кнопка «💊 Использовать» на карточке во вкладке «Персонаж → Предметы» и (для `consumable`) кнопка расходника в бою. На экране модуля отдельного использования нет. Для `hp_delta` / `o2_delta` / `hunger_delta` / `ammo_delta` / `skill_points_add` UI показывает действие (`EffectResolver.describe_effect`): «+30 HP», «+90 O2», «-40 голода», «+6 патр.», «+1 очк. навыков» — строкой «При использовании: …» на карточке, в кнопке «💊 Использовать (+30 HP)» и в кнопке боя «Аптечка ×2 (+30 HP)». Еда — `hunger_delta` с отрицательным значением (`ration_bar`: −40) |
| `equip_slot` | Слот снаряжения: `head` (шлем), `body` (тело), `arms` (руки — оружие или инструмент), `legs` (ноги), `back` (спина). Без поля предмет не надевается |
| `firearm` | `true` — огнестрел (сейчас `service_pistol`): только с `equip_slot: arms`. Манёвр «Выстрелить» доступен, лишь когда такой предмет надет в «Руки» и есть патроны |
| `stats` | Бонусы к характеристикам, пока предмет надет (см. «Характеристики») |
| `interactions` | Особые действия с предметом (см. ниже) |
| `unlocks` | Список id замков, которые открывает этот ключ (см. «Ключи и замки») |

### Взаимодействия предмета

Кнопки на карточке предмета во вкладке «Предметы». Кнопка видна, пока выполнены `requires`.

```json
"interactions": [
  {
    "id": "read",
    "label": "Прочитать записи",
    "requires": [ { "type": "flag", "flag": "datapad_read", "value": false } ],
    "text": "Запись добавлена в Архив.",
    "effects": [ { "type": "unlock_lore", "id": "log_01" }, { "type": "flag_set", "flag": "datapad_read" } ],
    "consume": false
  }
]
```

| Поле | Назначение |
|---|---|
| `id` | Уникален в пределах предмета |
| `label` | Текст кнопки |
| `requires` | Условия доступности. Чтобы действие было разовым — ставьте флаг в `effects` и проверяйте его здесь |
| `effects` | Эффекты |
| `text` | Сообщение после выполнения |
| `consume` | `true` — предмет расходуется |

Стандартные действия («Использовать», «Надеть», «Выбросить») описывать не нужно: UI добавляет их сам по `use_effect`, `equip_slot` и `category`.

## Ключи и замки

**Ключ** — предмет категории `key` со списком `unlocks`. Он не занимает слот сумки (`slot_cost: 0`) и не выбрасывается, чтобы забег нельзя было заблокировать:

```json
"hex_key": {
  "name": "Шестигранный ключ",
  "category": "key",
  "slot_cost": 0,
  "stackable": false,
  "description": "Открывает служебные панели и инструментальные ящики.",
  "unlocks": [ "service_panel", "tool_crate" ]
}
```

**Замок** — одинаковый объект и для узла карты, и для события:

```json
"lock": { "key": "tool_crate", "consume": false, "text": "Шестигранник проворачивает замок." }
```

| Поле | По умолчанию | Назначение |
|---|---|---|
| `key` | — | id замка; хотя бы один предмет должен открывать его, иначе валидатор ругается |
| `consume` | `false` | `true` — ключ расходуется при открытии (одноразовая карта-пропуск) |
| `text` | «Замок поддался.» | Что игрок видит в момент открытия |

Где ставить:
- **Закрытый отсек** — поле `lock` у узла сектора в состоянии `locked`. С ключом клик по узлу открывает его и сразу заводит игрока внутрь; без ключа карта пишет причину. Пока отсек не разведан, название нужного ключа не показывается.
- **Запертый ящик** — поле `lock` у ручного события локации. Событие видно в меню модуля неактивной кнопкой с подписью, какой ключ нужен.

Один ключ может открывать несколько замков (`unlocks` — список), а один замок — открываться разными ключами. Для условий в контенте есть `has_key`.

Готовая цепочка в `wreck_01`: `hex_key` лежит под погрузчиком в грузовом отсеке (`sit_1_5_forklift`) → открывает служебную панель узла `maintenance_bay` и инструментальный ящик внутри → в ящике `cargo_key` → он одноразово вскрывает рундук такелажника в грузовом отсеке.

## Пиксельный арт

Картинки лежат в `assets/art`:
- `scenes/<image>.png` — 160×96, иллюстрация сцены. На неё ссылаются поля `image` у ситуации, локации, варианта описания локации (`descriptions[].image`) и события;
- `items/<item_id>.png` — 16×16, иконка предмета. Отдельного поля нет: файл ищется по id предмета.

Рисует их генератор `tools/make_pixel_art.py` (чистый Python, без зависимостей): `python tools/make_pixel_art.py` перерисовывает весь набор. Новый кадр — новая функция в генераторе и запись в **конце** списка `SCENES` (вставка в середину сдвинет seed и перерисует соседние кадры); другое состояние того же отсека — через общий хелпер комнаты (как `cargo_drone` / `cargo_drone_down`). После добавления файлов нужно один раз запустить импорт Godot (`Godot --headless --path . --import`), иначе движок не увидит текстуру.

Правила показа: на экране ситуации — её `image`; на экране модуля — `image` сработавшего события, иначе `image` активного варианта описания (первого из `descriptions`, чьи `requires` выполнены), а если у него картинки нет — `image` самой локации. После победы картинка модуля обновляется сразу: флаг из `on_win` включает вариант, и грузовой отсек показывает лежащего дрона. Отсутствующая картинка — не ошибка: блок просто не рисуется.

## Характеристики

Суммируются из надетых предметов (`stats`) и навыков (`per_level × уровень`).

| Ключ | Название в UI | Действие |
|---|---|---|
| `armor` | Броня | Вычитается из каждого попадания врага (минимум 1 урона) |
| `melee_damage` | Урон в ближнем бою | Прибавляется к урону атаки без патронов (база 8) |
| `ranged_damage` | Урон в дальнем бою | Прибавляется к урону выстрела из огнестрела (`firearm`) с патронами (база 15) |
| `hit_chance` | Точность | Прибавляется к шансу попадания (`0.05` = +5%), не выше 95% |
| `flee_chance` | Шанс побега | Вычитается из `flee_risk` врага (`0.15` = −15% риска), не ниже 5% |
| `max_hp` | Макс. HP | Прибавляется к `start_hp` |
| `inventory_slots` | Слоты сумки | Прибавляется к `inventory_slots` из config |
| `explore_rolls` | Поиски в отсеке | Прибавляется к `explore.rolls` каждого модуля с пулом |
| `find_chance` | Шанс лишней находки | Шанс (`0.25` = 25%), что `item_add` из пула исследования даст на 1 предмет больше |

## Исследование — `explore_pools.json`

Кнопка «🔍 Исследовать отсек · осталось N из M» запускает поиск длиной `location.explore.duration` тактов. Результат выбирается до анимации и не меняется по ходу поиска. В центре экрана появляется блокирующая плашка; её шкала непрерывно заполняется за всё время поиска, а подпись обновляется по тактам. Каждые 0,5 секунды списывается цена `o2_costs.explore_tick` с учётом герметичности; силы и голод списываются один раз как `action` после последнего такта. Затем исследование либо находит скрытое событие модуля (`discover: true`), либо вытягивает случайное событие из пула (`explore.pool`). Если доступно и то и другое, выбор случаен пропорционально их числу. Всего исследований `M` = скрытые события + `rolls` + `explore_rolls` навыка; найденное и вытянутое сохраняется в забеге. Скрытое событие, чьи `triggers` ещё не выполнены, не находится, но остаётся в счётчике; если остаются только такие события, кнопка неактивна и пишет «Пока искать нечего».

```json
{
  "cryo_bay": [
    { "id": "loose_panel", "weight": 5,
      "text": "За отошедшей панелью обслуживания капсул — моток изоленты, прихваченный к кабелю.",
      "effects": [ { "type": "item_add", "item": "duct_tape" } ] },
    { "id": "revival_pack", "weight": 2,
      "text": "В лотке у изголовья капсулы — питательный гель «для первого часа после пробуждения». Он ещё не замёрз.",
      "effects": [ { "type": "hunger_delta", "value": -15 } ] }
  ]
}
```

| Поле | Назначение |
|---|---|
| `id` | Уникален в пределах пула |
| `weight` | Положительное целое: вес при случайном выборе |
| `text` | Текст в ленте |
| `effects` | Только `item_add`, `o2_delta`, `hp_delta`, `hunger_delta`, `ammo_delta`. Может быть пустым |
| `requires` | Необязательные условия: событие тянется, только если они выполнены |

Правила:
- Каждое событие пула выпадает в одном модуле не больше раза; один пул могут делить несколько локаций (счёт ведётся по локации).
- Скрывать (`discover`) стоит находки — «обыскать», «прочитать», «разобрать», «вскрыть шкафчик». Сюжетные действия (двери, ключ-карты, шлюз, завал, консоль, тарелка, установка элемента, стыковка спасения) оставляйте видимыми, иначе игрок не поймёт, куда идти. У скрытого события пишите `found`.
- Пул делайте больше `rolls` хотя бы на 2 (иначе предупреждение валидатора): навык «Поиск» добавляет броски, и выбор должен оставаться случайным.
- Смешивайте находки, опасности (`hp_delta`, `o2_delta` с минусом), небольшие пополнения O2 и атмосферные записи без эффектов — тексты о прошлом корабля и загадках сектора.
- Сейчас 12 пулов: `cryo_bay`, `bridge`, `cargo_hold`, `workshop`, `vacuum_corridor`, `reactor`, `alien`, `station_dock`, `station_living`, `station_medical`, `station_tech`, `outside`; `explore` есть у всех 12 локаций.

```json
"plate_vest": {
  "name": "Жилет из обшивки",
  "result": { "item": "plate_vest", "count": 1 },
  "ingredients": [
    { "item": "scrap_metal", "count": 2 },
    { "item": "duct_tape", "count": 1 }
  ],
  "requires": [ { "type": "skill_gte", "skill": "engineering", "value": 1 } ]

```

| Поле | Назначение |
|---|---|
| `name` | Заголовок рецепта (иначе имя результата) |

## Экран персонажа

Кнопка «Персонаж» в HUD открывает оверлей из трёх закреплённых вкладок; при прокрутке карточек заголовок и переключатели остаются сверху:

1. **🎒 Предметы** — две закреплённые подвкладки. **Сумка** показывает только физические вещи, занимающие место, без декоративной сетки пустых ячеек. **Записи и ключи** показывает `quest` и `key`, которые места не занимают. Карточка содержит категорию, слот, место, описание, бонусы и действия «Использовать», «Надеть», взаимодействия из `interactions`, «Выбросить».
2. **Снаряжение** — схематичный персонаж со слотами «Шлем», «Тело», «Руки», «Ноги», «Спина». Клик по слоту показывает надетый предмет («Снять») и подходящие предметы из сумки («Надеть»). Ниже — итоговые характеристики.
3. **Навыки** — строка «Уровень N · опыт x/y · новый уровень: +K очк. навыков», очки навыков, уровни, бонусы за уровень, кнопка «Изучить». Пока есть неистраченные очки, вкладка называется «Навыки (+N)», а у кнопки «Персонаж» в HUD стоит «(!)». Кнопки «Закрыть» нет — экран закрывается кнопкой «Персонаж».

При смене снаряжения прежний предмет слота возвращается в сумку. Если места не хватает (например, при снятии рюкзака с полной сумкой), действие отклоняется с сообщением. В бою и на экране смерти экран персонажа недоступен.

Вещи, не поместившиеся или выброшенные в модуле, показываются там карточками. **Применить** доступно для предмета с `use_effect`: эффект срабатывает на месте, один расходник удаляется со склада. **Подобрать** переносит в сумку столько экземпляров, сколько помещается; остаток остаётся на полу.

## Секторы — `sectors/<id>.json`

Узловая карта. Сектор делится на палубы (`floors`), между которыми игрок перемещается на лифтах.

```json
{
  "id": "wreck_01",
  "title": "Обломок «Персефона»",
  "hub_node": "hub",
  "map": { },
  "nodes": { "<node_id>": { } }
}
```

`hub_node` — узел-хаб. Его локация служит точкой чекпойнта, а при новой игре игрок начинает в ней.

**Переход между секторами.** Опция ситуации с `next: "map:<sector_id>"` загружает другой сектор и пишет чекпойнт. Так устроен перелёт с «Персефоны» на «Вехтер-9»: событие `install_power_cell` в `alien_shuttle` открывает `sit_3_4_departure`, та тратит `power_cell` и уводит в `wreck_02`. Сектор в забеге ровно один: при загрузке нового состояния узлов и туман предыдущего не сохраняются, поэтому перелёт делайте односторонним либо возвращайте игрока событием, которое заново открывает нужные узлы.

### Блок `map` (оформление карты)

Если задано хотя бы одно из `grid_columns`, `grid_rows` или `cell_size`, карта работает в **сеточном режиме** и узлы ставятся по `cell`. Иначе действует **свободный режим** с координатами `position` внутри `size`.

| Поле | По умолчанию | Назначение |
|---|---|---|
| `viewport_height` | 620 (минимум 560) | Высота виджета карты в пикселях |
| `grid` | `true` | Рисовать ли сетку |
| `grid_columns`, `grid_rows` | 7, 5 | Размер сетки в клетках |
| `cell_size` | `{x:118, y:112}` | Размер клетки в виртуальных единицах |
| `module_size` | `{x:74, y:74}` | Размер иконки узла (итоговая сторона ограничена 48..84 px) |
| `size` | `{x:900, y:620}` | Виртуальный размер карты (свободный режим) |
| `grid_step` | 90 | Шаг сетки (свободный режим) |
| `floor_buttons_side` | `"right"` | С какой стороны колонка кнопок палуб: `left` или `right` |
| `default_floor` | первая в `floors` | Палуба, на которой начинается игра |
| `floors` | `[]` | `[{ "id", "label" (текст на кнопке), "title" (подсказка, название палубы в маршруте) }]`. Кнопки показываются только для палуб, где игрок уже побывал, и только если таких больше одной |

### Узел

| Поле | По умолчанию | Назначение |
|---|---|---|
| `title` | — | Полное название (подсказка на узле, заголовок локации по умолчанию) |
| `location_id` | `""` | Локация модуля. Обязательна для каждого узла, кроме лифтов; у закрытого узла может временно отсутствовать (предупреждение валидатора) |
| `connections` | `[]` | id соседних узлов (связь работает в обе стороны). По ним рисуются линии и прокладывается маршрут игрока |
| `sealed` | `true` | `false` — отсек без давления: переход в него и любые действия внутри стоят дороже (`o2_unsealed_multiplier`) |
| `state` | `"locked"` | Одно из состояний ниже |
| `map` | `{}` | Оформление узла, см. следующую таблицу |
| `lock` | — | Замок закрытого отсека: `{ "key": "<id замка>", "consume": false, "text": "..." }`. Узел в состоянии `locked` можно выбрать целью маршрута, если подходящий ключ уже в сумке: замок открывается, когда игрок до него дойдёт (см. «Ключи и замки») |

Поле `situation_id` устарело: валидатор считает его ошибкой. Ситуации привязываются к событиям локаций.

Состояния узла:

| `state` | На карте | Можно войти |
|---|---|---|
| `locked` | Синий 🔒 (с ключом в сумке — 🔑); при тумане войны виден только рядом с разведанной зоной | только с ключом, и только как цель маршрута |
| `available` | По статусу: жёлтый ❗ — есть что сделать, синий 🔒 — остались действия под ключ, серый ✓ — пусто; `?` до первого визита | да |
| `dangerous` | Красный ☠ | да |
| `cleared` | По статусу, как `available` | да |

Модуль-база (`base: true`) всегда зелёный 🏠, лифт — голубой 🛗 с подписью «Лифт к <label палубы назначения>», у отсека без давления значок 💨. Статус считается по содержимому локации: доступные ручные события, ждущее автособытие, вещи на полу, есть что исследовать.

**Маршрут и перехват.** Игрок ходит только по `connections`, через видимые незапертые узлы. Транзитный модуль останавливает игрока, только если вход в него начнёт бой (доступное автособытие с `start_combat` в эффектах или в вариантах его ситуации) — игрок входит туда, как при обычном визите. Прочие автособытия (сообщения, предупреждения, находки) в пути не срабатывают — они ждут, когда игрок войдёт в модуль сам. Поэтому враг в проходном отсеке «держит» проход: отступить (`next: "map:<этот сектор>"`) — вернуться туда, откуда пришёл; бежать из боя посреди маршрута — прорваться дальше.

До нахождения схемы корабля видны только посещённые отсеки и соседние с ними. Палубы, где игрок ещё не был, не видны вовсе — даже после схемы. После `reveal_map` на знакомых палубах туман снимается, но состояние `locked` по-прежнему запрещает вход. Узел с `map.hidden_until_open: true` остаётся полностью скрытым даже после `reveal_map`, пока действие с эффектом `open_map_node` не откроет его.

Камера карты двигается перетягиванием одним пальцем или мышью. Щипок двумя
пальцами, жест тачпада, колесо и кнопки «＋/－» меняют масштаб; «◎» возвращает
камеру к игроку. Карта, открытая во время ситуации, остаётся интерактивной для
камеры, но становится серой, получает watermark «ЗАБЛОКИРОВАНО» и не позволяет
выбирать отсеки.

Поля `map` узла:

| Поле | Назначение |
|---|---|
| `label` | Короткая подпись под иконкой (иначе `title`). У лифтов не задаётся: подпись «Лифт к …» собирается из `target_floor` |
| `floor` | id палубы (иначе `default_floor`) |
| `cell` | `{x, y}`, клетка сетки, **нумерация с 1** |
| `position` | `{x, y}`, координаты в свободном режиме |
| `order` | Порядок сортировки узлов |
| `note` | Дополнительная строка в подсказке |
| `kind` | `"elevator"` — узел является лифтом (локации не имеет) |
| `target_floor` | Для лифта: id палубы назначения (обязательно); её `label` идёт в подпись «Лифт к 02» |
| `hidden_until_open` | `true` — не показывать узел ни по соседству, ни после `reveal_map`, пока его состояние `locked` |
| `reveal_title_when_locked` | `true` по умолчанию. `false` — подпись закрытого узла «Неизвестно» |

**Лифт в обе стороны** — это два узла: по одному на каждой палубе, у каждого свой `target_floor`, и они связаны друг с другом в `connections` (поездка — шаг маршрута между ними; без связи валидатор выдаёт ошибку). Пример: `lift_01_to_02` и `lift_02_to_01` в `wreck_01.json`.

## Враги — `enemies.json`

```json
"station_sentry": {
  "name": "Турель охраны",
  "hp": 45,
  "ai": "turret",
  "attack": { "min": 8, "max": 16, "hit_chance": 0.55, "range": 5 },
  "start_range": 4,
  "preferred_range": 5,
  "weapon": "спаренный ствол на подвесе",
  "flee_risk": 0.3,
  "loot": ["scrap_metal", "duct_tape"],
  "xp": 30,
  "special_actions": [
    {
      "id": "jam_optics",
      "label": "Залепить оптику турели ветошью",
      "requires": [ { "type": "has_item", "item": "cloth_rags" } ],
      "effect": { "type": "distract", "value": 2 }
    }
  ]
}
```

| Поле | По умолчанию | Назначение |
|---|---|---|
| `hp` | — | Запас прочности |
| `ai` | `"brawler"` | `brawler` — лезет в ближний бой; `shooter` — держит `preferred_range`; `turret` — не двигается вовсе |
| `attack.range` | `1` | Максимальная дистанция, с которой враг достаёт игрока (1…5) |
| `attack.min` / `attack.max` / `attack.hit_chance` | — | Разброс урона и шанс попадания |
| `start_range` | `3` | Дистанция в начале боя (0…5) |
| `preferred_range` | `attack.range` | Дистанция, которую держит `shooter` |
| `weapon` | `""` | Подпись «Оружие» в карточке противника |
| `flee_risk` | `0.5` | Вероятность **неудачного** побега вплотную; каждый шаг дистанции снижает её на 0.08, с 4 шагов побег гарантирован |
| `loot` | `[]` | Что падает при победе |
| `xp` | `config.xp.kill` | Опыт за победу (неотрицательное целое). Сейчас: дрон 25, турель 30, Штамм Л-7 50 |
| `special_actions` | `[]` | Спецдействия игрока против этого врага: каждое доступно один раз за бой. Единственный тип эффекта — `distract`: враг теряет цель на `value` ходов (урона это не наносит), а первый удар по отвлечённому врагу проходит без броска |

Описывать общие для всех схваток манёвры не нужно: «✋ Подобрать обломок» и «🪨 Бросить обломок» (попадание — немного урона и потерянный врагом ход) есть в любом бою, см. [«Бой»](ARCHITECTURE.md#бой).

## Лор — `lore.json`

```json
"log_01": { "title": "Заголовок", "text": "Текст фрагмента" }
```

Фрагменты открываются эффектом `unlock_lore` и видны в журнале на вкладке «Архив». Открытые фрагменты переживают смерть (meta-слой).

## Справочник мира — `codex.json`

```json
"persephone": {
  "category": "ships",
  "title": "«Персефона»",
  "aliases": ["«Персефоны»", "Персефона"],
  "text": "Описание, которое увидит игрок после первого упоминания."
}
```

Допустимые категории фиксированы: `places` («Места»), `people` («Люди»), `ships` («Корабли»), `terms` («Термины»). `title` и все непустые `aliases` участвуют в регистронезависимом поиске по текстам ленты, целей, хроники и Архива. Совпадения ищутся от длинных к коротким без вложенных перекрытий. Первое упоминание открывает статью в meta-слое, ставит уведомление «Журнал (!)» / «Справочник (!)»; открытые понятия подсвечиваются цветом `UiKit.CODEX_COLOR`. Новая игра их не закрывает.


## Цели и мысли — `quests.json`

```json
{
  "thoughts": [
    { "requires": [{ "type": "flag", "flag": "left_persephone" }], "text": "«Персефона» осталась позади." },
    { "requires": [], "text": "Сначала выбраться из капсулы гибернации." }
  ],
  "quests": [
    {
      "id": "rigger_keys",
      "title": "Ключи такелажников",
      "description": "Что открывает этот ключ?",
      "start": [{ "type": "has_item", "item": "hex_key" }],
      "steps": [
        { "id": "open_box", "text": "Вскрыть ящик в техотсеке", "done": [{ "type": "event_done", "event": "tech_bay/open_box" }] },
        { "id": "clue", "text": "Найти записку такелажника", "done": [{ "type": "flag", "flag": "rigger_note" }], "hidden": true }
      ]
    }
  ]
}
```

- `thoughts` — варианты мыслей героя: показывается первый, чьи `requires` выполнены. Поздние этапы сюжета ставьте первыми, последний вариант — без условий (иначе валидатор предупредит).
- `quests[]`: `id` (уникальный), `title`, `description`, `start` (опц., условия старта; без поля цель начинается сразу), `steps` (непустой массив), `done` (опц., условия выполнения цели).
- `steps[]`: `id` (уникальный внутри цели), `text`, `done` — непустые условия; `hidden: true` — шаг-улика, не виден, пока не засчитан.
- Шаг засчитывается, как только выполнен его `done`, в любом порядке. Цель выполнена по своему `done`, а без него — когда засчитаны все шаги. Засчитанное не откатывается: условие «есть предмет» достаточно выполнить один раз.
- В журнале видны засчитанные шаги (✓) и первый незасчитанный не скрытый (▸); следующие не раскрываются, поэтому шаги пишите в порядке прохождения.
- Условия — обычные `requires` (см. [«Условия»](#условия-requires--triggers)); в `event_done` — полный id «локация/событие».
- Проверка идёт после каждого применения эффектов и завершения события; появление цели, шага и выполнение цели видно в ленте («[Новая цель: …]», «[✓ шаг]», «[Цель выполнена: …]») и в «Хронике».

## Финалы — `endings.json`

```json
"rescue_colony": { "title": "Спасательный бот Мейер-4", "text": "Текст финала. Поддерживаются переводы строк \n." }
```

Финал показывается экраном победы, когда сработал эффект `end_run` с этим id. Валидатор требует непустые `title` и `text` и предупреждает о финале, на который никто не ссылается. Хроника (`ChronicleSystem`, meta-слой) считает победы и запоминает, какие финалы игрок уже видел, — на экране победы это строка «Финалов открыто: X из Y».

Развилку финалов удобно делать флагом: `sit_4_3_beacon` записывает `beacon_target` (`colony` / `fleet`), а `sit_4_4_rescue` показывает тот вариант, чьё условие `{"type": "flag", "flag": "beacon_target", "value": "colony"}` выполнено.

## Рецепты контента

### Новый модуль

1. Создать `data/locations/<id>.json` с `description` и событиями; находки сделать скрытыми (`discover` + `found`), задать `explore` с подходящим пулом из `explore_pools.json`.
2. В секторе прописать узлу `"location_id": "<id>"`, `floor`, `cell` и связи.
3. Открыть узел:
   - сразу — `"state": "available"`;
   - позже — `"state": "locked"` плюс эффект `open_map_node` в каком-нибудь событии.
4. `python tools/validate_content.py` → пройти в игре.

### Закрытая дверь, которую игрок открывает сам

Ручное разовое событие с условием и эффектом `open_map_node`:

```json
{ "id": "open_door", "start": "manual", "label": "Вскрыть дверь", "repeatable": false,
  "triggers": [ { "type": "has_item", "item": "pipe_scrap" } ],
  "text": "Дверь поддаётся.",
  "effects": [ { "type": "open_map_node", "node": "next_room" } ] }
```

### Враг, который ждёт в модуле, пока его не победят

Повторяемое автособытие с триггером по флагу, флаг выставляется в `on_win`:

```json
{ "id": "drone_encounter", "start": "auto", "repeatable": true,
  "triggers": [ { "type": "flag", "flag": "drone_cargo_down", "value": false } ],
  "situation": "sit_1_3_drone" }
```

В ситуации:

```json
"effects": [ { "type": "start_combat", "enemy": "drone_cargo", "clear_node": "cargo_bay",
               "on_win": [ { "type": "flag_set", "flag": "drone_cargo_down" },
                           { "type": "skill_points_add", "value": 1 } ] } ]
```

### Сообщение при первом входе

```json
{ "id": "first_look", "start": "auto", "repeatable": false, "triggers": [],
  "text": "Здесь пахнет гарью." }
```

### Базовая функция модуля (доступна всегда)

```json
{ "id": "inspect", "start": "manual", "label": "Осмотреться", "repeatable": true,
  "triggers": [], "text": "Ничего нового." }
```

### Цепочка событий

Второе событие ждёт первое через `event_done`. Так в `hub.json` сделано вступление: `awakening` → `wreckage`.

### Новый предмет снаряжения

1. В `items.json` задать `equip_slot` и `stats`, `stackable: false`.
2. Выдать его эффектом `item_add` в событии, луте врага или рецепте.

### Рецепт только у верстака и с навыком

```json
"requires": [
  { "type": "in_location", "location": "workshop" },
  { "type": "skill_gte", "skill": "engineering", "value": 2 }
]
```

### Действие модуля, доступное только с навыком

```json
{ "id": "fix_panel", "start": "manual", "label": "Починить панель", "repeatable": false,
  "triggers": [ { "type": "skill_gte", "skill": "engineering", "value": 1 } ],
  "text": "Панель оживает.", "effects": [ { "type": "open_map_node", "node": "reactor" } ] }
```

### Запертый ящик и ключ к нему

1. В `items.json` — ключ: `"category": "key"`, `"slot_cost": 0`, `"unlocks": ["tool_crate"]`.
2. Выдать ключ игроку (`item_add` в событии, ситуации или луте).
3. В локации — ручное событие с `lock`:

```json
{ "id": "open_tool_crate", "start": "manual", "label": "Вскрыть инструментальный ящик",
  "repeatable": false, "triggers": [],
  "lock": { "key": "tool_crate", "consume": false },
  "text": "В ящике — запасной баллон.", "effects": [ { "type": "item_add", "item": "o2_canister" } ] }
```

Для закрытого отсека то же самое пишется в узле сектора (состояние `locked` + `lock`).

## Что проверяет валидатор

- JSON корректен; у ситуаций, секторов и локаций есть `id`; id не дублируются, в том числе id событий внутри локации и взаимодействий внутри предмета.
- `config.json`:
  - стартовый сектор и вступительная ситуация существуют;
  - `start_equipment` — существующие предметы в правильных слотах;
  - `start_skill_points` — неотрицательное целое;
  - `xp` — объект только с ключами `XP_CONFIG_KEYS` (`explore`, `craft`, `lore`, `kill`, `level_base`, `level_step`, `skill_points_per_level`), значения — неотрицательные целые, `level_base` и `level_step` не оба нулевые;
  - `needs` — объект только с ключами `NEEDS_CONFIG_KEYS`, значения — неотрицательные числа, `max_energy` и `max_hunger` больше нуля; `energy_costs` / `hunger_costs` — объекты с действиями из `o2_costs`.
- `quests.json`: у `thoughts` есть `text` и корректные `requires` (предупреждение, если у последнего варианта есть условия); id целей уникальны, есть `title`, `start` и `done` корректны; `steps` непустые, id шагов уникальны, у шага есть `text`, `hidden` булев, `done` непустой и корректный.
- Локации: `base` и `breathable` булевы; варианты `descriptions` — объекты с непустым `text`, корректными `requires` и существующей картинкой `image`; `explore` — объект с существующим `pool`, целым `rolls ≥ 0` и `duration: [min, max]` из двух положительных целых, где `min ≤ max` (предупреждение, если в пуле меньше `rolls + 2` событий).
- `codex.json`: четыре фиксированные категории; у каждой записи непустые `title` и `text`, `aliases` — массив непустых строк; id, заголовки и псевдонимы не дублируются без учёта регистра.
- Узлы:
  - `location_id` ссылается на существующую локацию;
  - доступный узел без локации — ошибка, закрытый — предупреждение;
  - `situation_id` — ошибка (устарело).
- События:
  - `start` равен `auto` или `manual`;
  - у `manual` есть `label`;
  - `repeatable` булев;
  - `discover` булев и только у `manual`; скрытое событие без `found` — предупреждение;
  - `clear_image`, если задан, булев;
  - `situation` существует;
  - событие что-то делает.
- Предметы:
  - `equip_slot` — один из пяти слотов;
  - `stats` — известные характеристики с числами;
  - у взаимодействий есть `id` и `label`;
  - надеваемый и стакаемый предмет — предупреждение;
  - `unlocks` — массив непустых строк; ключ без `unlocks` и предмет с `unlocks` вне категории `key` — ошибка и предупреждение соответственно;
  - у `quest` и `key` `slot_cost` равен 0;
  - `firearm` булев и только с `equip_slot: arms`.
- Ситуации: у каждого варианта есть непустой `result` (без него игроку нечего показать перед «Продолжить»).
- Замки (`lock` у узла и у события): `key` существует хотя бы у одного предмета, `consume` булев, `text` строковый. Замок на незакрытом узле — предупреждение.
- Картинки: файл `assets/art/scenes/<image>.png` существует для каждого `image` у локации, варианта её описания, события и ситуации.
- Звуки событий: файл `assets/sounds/<sound>.wav` существует для каждого заданного `events[].sound`.
- Враги: `ai` из списка, `attack.range` — целое 1…5, `start_range` и `preferred_range` — 0…5, `xp` — неотрицательное целое.
- Навыки: `name`, `max_level`, `cost`, характеристики в `per_level`.
- `explore_pools.json`: пулы непустые, id событий уникальны, есть `text`, `weight` — положительное целое, `requires` и `effects` корректны, типы эффектов только из разрешённых; пул, на который не ссылается ни одна локация, — предупреждение.
- Рецепты: результат и материалы существуют, количества — положительные целые, условия корректны.
- Ссылки существуют:
  - на ситуации;
  - на сектора в `map:<id>`;
  - на предметы;
  - на лор;
  - на врагов;
  - на узлы (`open_map_node` не может открыть узел без локации);
  - на палубы;
  - на события в `event_done`;
  - на навыки в `skill_gte`;
  - на локации в `in_location`.
- Эффекты в `on_win` и `on_flee` проверяются так же, как обычные. У `item_add` и `item_remove` `count` — положительное целое.
- Геометрия карты: положительные размеры, клетки в пределах сетки, два узла в одной клетке (предупреждение), у лифта задан `target_floor`.
- Недостижимые ситуации и локации, не привязанные к узлам (предупреждения).

Валидатор **не** ловит логические тупики, например события, триггеры которых никогда не выполнятся, или рецепты, материалов для которых в игре не достать.
