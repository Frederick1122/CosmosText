# Разработка

## Окружение

| Что | Версия | Зачем |
|---|---|---|
| Godot | 4.7 (проверялось на 4.7.2), стандартная сборка без .NET | Движок, редактор, запуск, смоук-тест |
| Python | 3.10+ | `tools/validate_content.py` (только стандартная библиотека) |
| uv | любая свежая | Только для MCP-сервера (см. [MCP.md](MCP.md)) |

## Запуск

1. Godot → Import → выбрать `project.godot`.
2. **F5** — главная сцена `scenes/Game.tscn`.
3. Параметры окна: вьюпорт 1080×1920, портретная ориентация, `stretch/mode = canvas_items`, рендерер Mobile.

Если окно не помещается на монитор, уменьшите его в *Project Settings → Display → Window → Size → Window Width/Height Override* (например 540×960). Не коммитьте это изменение, если оно нужно только вам.

## Проверки

### Контент

```bash
python tools/validate_content.py
```

Если в консоли Windows выводятся кракозябры или падает `UnicodeEncodeError`, запустите так:

```bash
PYTHONIOENCODING=utf-8 python tools/validate_content.py
```

### Пиксельный арт

```bash
python tools/make_pixel_art.py                      # перерисовать assets/art
Godot_v4.7.2-stable_win64_console.exe --headless --path . --import   # импорт новых PNG
```

Генератор детерминирован (фиксированный seed) и переписывает весь набор: сцены 160×96 и заставку меню 240×150 в `assets/art/scenes`, иконки предметов 16×16 в `assets/art/items`, боевые портреты 64×64 в `assets/art/portraits` и `assets/art/enemies`. Без импорта Godot новые файлы не видны движку, и картинка просто не покажется.

**Осторожно:** запуск Godot с `--import` поднимает редактор и может сбросить пути Android SDK/JDK в `%APPDATA%\Godot\editor_settings-4.7.tres`. После импорта проверьте `export/android/android_sdk_path`, `export/android/java_sdk_path` и `export/android/debug_keystore` — они должны указывать в `D:\Repos\CosmoToolchain` (см. «Экспорт под Android»), иначе сборка APK упадёт на «Каталог build-tools отсутствует».

### Звуки

```bash
python tools/import_sounds.py "D:/Repos/400 Sounds Pack"   # перенести и выровнять assets/sounds
Godot_v4.7.2-stable_win64_console.exe --headless --path . --import   # импорт новых WAV
```

Скрипт берёт из библиотеки только файлы из своей таблицы `SOUNDS` (22 звука, соответствие id → файл библиотеки — там же), сводит в моно, срезает тишину и выравнивает громкость. Библиотека в репозиторий не входит, в `assets/sounds` лежат уже обработанные `<id>.wav`. Лицензии в папке библиотеки нет — перед публикацией в сторе её нужно подтвердить. В смоук-тесте (`--headless`) звук отключён; проверять на слух — в запущенной игре, настройки «Звук» и «Громкость» в экране «Настройки».

### Смоук-тест логики

`scenes/Main.tscn` проходит вертикальный срез через системы без UI и проверяет:
- **модули и события:** автособытия и цепочку по `event_done`, ручные разовые и повторяемые события, лифт, отступление и повторную встречу с дроном, бой с победой и `on_win`, открытие шлюза, возврат в пройденный модуль;
- **карта и путь:** игрок стоит в узле, палубы за лифтом скрыты до поездки, маршрут к нижнему лифту идёт через грузовой отсек и стоит переход плюс поездку, дрон перехватывает в пути, отступление возвращает в предыдущий узел, побег посреди пути — прорыв до палубы 03, место игрока и знакомые палубы переживают сохранение;
- **персонаж:** стартовое снаряжение, взаимодействие с предметом, запрет выбросить сюжетный предмет, надевание и снятие, бонусы брони, урона, слотов, побега и HP, `has_item` по надетому, изучение навыка, крафт с условием по навыку, уведомление о неистраченных очках навыков;
- **сохранение и загрузку** всего перечисленного;
- **кислород:** переход в отсек без давления стоит вдвое дороже, чем в загерметизированный, ручное событие и ход в бою списывают свою цену, баллон восполняет запас и сам его не тратит, переход с пустым баллоном убивает и не пускает в модуль;
- **журнал забега:** записи о переходах, боях и смерти, их число и переживание сохранения;
- **база:** флаг `base` у локации, склад (выложить/забрать), ручной чекпойнт;
- **ключи и замки:** запертый узел карты без ключа не открывается, с ключом открывается и пускает внутрь; многоразовый ключ остаётся в сумке, одноразовый расходуется; запертое событие-ящик сообщает о замке и не запускается; ключ не занимает слот и не выбрасывается;
- **буфер и ситуации:** старт события очищает описание локации, выбор кладёт реплику и результат, ситуация ждёт «Продолжить», после него событие заменяется следующим контекстом;
- **бой:** стартовая дистанция врага, удар только вплотную, сближение, цена хода по кислороду, отвлекающий манёвр не наносит урона и даёт верный удар;
- **надёжность сейвов:** поле `version`, отсутствие хвостов `.tmp`, отказ читать обрезанный и более новый сейв, запись лора в `meta.json` без смерти, автосохранение на экране модуля, его отсутствие в бою и сохранение по `NOTIFICATION_APPLICATION_PAUSED`;
- **второй сектор:** перелёт на шаттле (`install_power_cell` → `sit_3_4_departure` → `map:wreck_02`), отказ от старта, прибытие и чекпойнт в `dock_bay`, выбор в шкафчике, карта доступа и медблок, бой с турелью, аварийный баллон, разблокировка мачты и запуск маяка, сохранение прогресса `wreck_02`;
- **финал:** доступен только тот спасатель, которого звал маяк; отказ оставляет игрока на станции; победа переводит на экран `VICTORY`, пишет хронику в `meta.json` и удаляет `run.json`/`checkpoint.json`.

В редакторе: открыть `Main.tscn` и нажать **F6**. Из консоли — через консольную сборку Godot (`*_console.exe`):

```bash
Godot_v4.7.2-stable_win64_console.exe --headless --path . res://scenes/Main.tscn
```

В конце выводится `SMOKE OK` (код выхода 0) или `SMOKE FAIL` со списком упавших проверок (код 1).

Тест **перезаписывает `run.json`, `checkpoint.json` и `meta.json`** в `user://`; сохраните их, если нужны. В выводе намеренно появляются две ошибки `SaveManager: сейв ... повреждён / новее игры` — это проверки отказа загрузки. Строка `MCP Bridge Game: Failed to listen on port 9501` при прогоне нормальна, если параллельно запущена игра.

При изменении контента вертикального среза (`hub`, `cargo_bay`, `alien_shuttle`, `sit_1_*`, предметы, навыки, рецепты из среза) обновляйте проверки в `scenes/Main.gd`.

## Content Studio — встроенный редактор контента

Проект содержит Godot EditorPlugin `CosmoText Content Studio`. После открытия проекта он появляется в правом доке редактора. Если док скрыт: **Editor → Docks → CosmoText Content Studio**.

Редактор работает с теми же файлами, что и игра:

- **Карта** — сектор, палубы, отсеки, состояния, координаты сетки и связи;
- **Локации** — описание и события;
- **Ситуации** — текст, варианты выбора, условия и эффекты;
- **Предметы** — имя, категория, слоты, описание, использование и взаимодействия;
- **Крафты** — результат, ингредиенты и условия;
- **Журнал** — заголовок и текст заметки.

Порядок работы:

1. Выбрать раздел и ресурс.
2. Изменить поля или добавить отсек/событие/вариант.
3. Нажать **Сохранить**.
4. Нажать **Проверить весь контент** и отдельно запускать `python tools/validate_content.py` перед коммитом.

Редактор сохраняет JSON автоматически форматированным и запускает пересканирование файлов Godot. Условия, эффекты и ингредиенты редактируются строками с типом и параметрами; расширенные поля (например особые взаимодействия предметов и параметры карты) остаются отдельными JSON-полями, чтобы не потерять возможности схемы.

## Сохранения

Путь: `%APPDATA%\Godot\app_userdata\CosmoTextGame\` (в редакторе: *Project → Open User Data Folder*).

| Файл | Что внутри |
|---|---|
| `run.json` | Текущий забег: ресурсы, сумка, снаряжение и навыки, модули и события, карта |
| `checkpoint.json` | Точка отката |
| `meta.json` | Архив лора и экономика, переживают смерть |
| `logs/` | Логи запусков игры |

Когда какой файл пишется, описано в [ARCHITECTURE.md](ARCHITECTURE.md#сохранения).

**Сбросить прогресс** — удалить `run.json`, `checkpoint.json` и `meta.json`. Удаление `meta.json` сбрасывает архив и счётчик рекламных откатов.

## Ручная проверка вертикального среза

После изменений в UI пройдите сценарий целиком (логику без UI покрывает смоук-тест). На игровых экранах показатели и четыре кнопки HUD должны оставаться у нижнего края; прокручивается только содержимое над ними:

1. На главном меню заставка «Персефона» видна целиком, название, кнопки и статистика собраны по центру, версия стоит снизу. **Настройки** открываются и возвращают обратно. Затем **Новая игра** → автособытие «пробуждение» (`sit_1_1_capsule`). Выбрать вариант: под текстом появляется янтарная реплика игрока, под ней красная цена выбора `[−2 O2]`, затем текст последствия и кнопка «Продолжить». Нажать её: первое событие целиком исчезает, показывается только второе (`sit_1_2_wreckage`).
2. Выбрать «Взять планшет, не читать — потом» и нажать «Продолжить»: событие исчезает, появляется только заголовок, иллюстрация и описание модуля «Капсула». Кнопка «🧑‍🚀 Персонаж (!)» доступна сразу, во вкладке «⭐ Навыки (+1)»; после изучения навыка «(+1)» и «(!)» пропадают (если нет новых предметов). Во вкладке навыков нет «Закрыть». HUD: ❤️, 💨 O2, 🔫, 🎒 и двухстрочные кнопки со значками.
3. Экран модуля «Капсула» (это модуль-база): лента с иллюстрацией, заголовком и описанием. «Вскрыть аварийный контейнер под креслом» → «Оставить»: после «Продолжить» описание модуля возвращается, действие остаётся доступным; при повторном запуске контейнер можно вскрыть (если в капсуле выбрано «Прислушаться» — доступен вариант «Подгадать провал гравитации»). «Осмотреть капсулу» остаётся повторяемым. В разделе «База» есть «💾 Сохранить забег» и «🛠️ Верстак»; «Закрыть» верстака возвращает в капсулу. Если в сумке есть выбрасываемый предмет — появляется «Разложить по складу».
4. **Персонаж → Предметы:** у планшета кнопка «Прочитать записи» → сообщение, запись в «Архиве», кнопка исчезла. Кнопки «Выбросить» у планшета нет.
5. **Персонаж → Снаряжение:** на кукле «Тело — Лётный комбинезон», остальные слоты «пусто». Клик по слотам меняет подсветку; характеристики «Броня: +1».
6. «Карта» из капсулы открывается поверх модуля: над картой легенда цветов, капсула зелёная с 🏠, на ней фишка 🧑‍🚀, лифт голубой; палуб 02/03 справа нет. «Карта» ещё раз (или «Персонаж» → «Персонаж») возвращает в капсулу, а не на карту. Нажать лифт → жёлтый маршрут, под картой «📍 …», «≈ −N O2 · останется M», «▶️ Идти» / «✖ Отмена»; второе нажатие на лифт — в путь: камера приближается, фишка идёт к лифту, едет на палубу 02, справа появляются кнопки 01/02, камера отходит. Нажать нижний лифт «Лифт ↓»: маршрут через «Неизвестно» с предупреждением «❔ По пути неизвестные отсеки». «Идти» → фишка доходит до грузового отсека, и дрон перехватывает (своя картинка ситуации). «Отступить» → карта, игрок снова у лифта, отсек красный ☠. Проложить путь к нижнему лифту снова — предупреждение «☠ По пути враг». Пойти, «Войти и вступить в бой» → «Бежать» до отрыва → «Продолжить» → путь продолжается, игрок прорывается к лифту и уезжает на палубу 03. Вернуться и «Войти и вступить в бой»: экран боя показывает карточки сторон, линейку дистанции и сетку манёвров со значками; «Удар» недоступен, пока не сблизился. Каждый удар виден: карточка цели вздрагивает и вспыхивает, над портретом всплывает урон (или «мимо»), полоса HP стекает; удар по игроку на миг окрашивает экран красным. Добить дрона → «Победа» и «Продолжить»; игрок в модуле, в ленте `[+1 Металлолом]`, отсек жёлтый ❗, пока в нём есть действия, потом серый ✓.
7. «Обыскать контейнеры» → под репликой `[−3 O2]`, под текстом находки строками `[+1 Аптечка]`, `[+2 Изолента]` и т. д.; сумка 6/6. «Использовать: Аптечка» → «Использовано: Аптечка.» и под ней `[+N HP]`. В меню виден неактивный «Вскрыть рундук такелажника — Заперто. Нужен: Магнитный ключ такелажника».
8. **Персонаж → Предметы:** надеть «Обломок трубы». В слоте «Руки» — труба, «Урон в ближнем бою: +6».
9. Вернуться в «Капсулу» → **Верстак:** «Жилет из обшивки» подсвечен как недоступный (нужна Инженерия). Создать «Самодельный рюкзак» → **Персонаж → Предметы:** надеть его → «Сумка: …/9». Во вкладках персонажа крафта нет.
10. **Персонаж → Навыки:** очков 2 → изучить «Инженерию». **Верстак:** создать жилет → надеть: комбинезон ушёл в сумку, «Броня: +3».
11. Вернуться в «Грузовой»: шаттла на карте ещё нет. Нажать «Вскрыть шлюз к шаттлу» → в событии выделено `[Открыта новая локация "Чужой шаттл"]`, после выхода шаттл появился на карте. Внутри «Обыскать кабину» → надеть ботинки.
12. «Вытащить ящик из-под погрузчика» → в сумке шестигранный ключ (места в сумке не занял). На карте «Техотсек» синий 🔒 сменился на 🔑 с жёлтой рамкой: маршрут к нему открывает панель, ключ остаётся. Внутри «Вскрыть инструментальный ящик» → магнитный ключ. Вернуться в «Грузовой» → рундук теперь открывается, магнитный ключ исчезает из сумки.
13. Нажать на запертый узел, к которому нет ключа → под картой янтарная строка «Отсек: Заперто», маршрута нет, карта не сдвигается. Длинная подпись узла («Неизвестно» на крупном шрифте) едет бегущей строкой. Карту можно тащить пальцем/мышью, «＋/－» приближают, «◎» возвращает камеру к игроку. В пути работает «⏹ Стоп», кнопки HUD заперты. При малом запасе кислорода маршрут предупреждает «⚠️ После перехода останется ≈ N O2» или «⛔ Кислорода не хватит».
14. В бою: «Прицелиться» и «Уклоняться» доступны всегда, «Бежать» дешевеет с ростом дистанции, кнопка «Персонаж» неактивна, у обеих сторон видны портреты. Отвлекающий манёвр не отнимает HP врага: он получает «Потерял цель», игрок — «Верный удар».
15. Лифт на палубу 01 → «Капсула» (чекпойнт). Перезапустить игру → **Продолжить** → снаряжение и навыки на месте.
16. Намеренно умереть → экран смерти: иллюстрация причины (иней на визоре — кислород, коридор под аварийной лампой — раны), «ВЫ ПОГИБЛИ», причина и эпитафия; при смерти в бою — строка «Последний удар: …». Кнопки видны без прокрутки, под ними «Последние минуты» (три записи журнала) и счётчики хроники. Проверить «Вернуться к чекпойнту» и «Начать заново».
17. Дойти до реактора, забрать энергоячейку → шаттл → «Поставить энергоячейку в гнездо шаттла» → «Заглушить панель»: игрок в шаттле, ячейка в сумке, действие доступно снова.
18. Повторить и выбрать старт → карта «Ретранслятор „Вехтер-9"», ярус A, узел «Стыковка» зелёный (хаб). Войти: автособытие прибытия и запись в «Журнале».
19. «Каюты» → «Обыскать койки», «Вскрыть шкафчик» → взять карту доступа. Медблок на карте ещё не виден. «Снять карантин с двери медблока» → выделено открытие, на карте появился «Медблок».
20. Лифт на ярус B → «Связь»: мачта скрыта, отсек без давления, каждое действие и ход в бою съедают вдвое больше `O2`; турель стреляет с дистанции и не подходит. Победить → «Перебрать консоль наведения» → выделено открытие, на карте появилась «Антенна» → «Навести тарелку» → выбор адресата, после него описание мачты меняется.
21. После маяка вернуться в «Стыковку» → «Открыть шлюз пришедшему кораблю»: доступен только тот корабль, которого звал маяк. Отказ («сначала забрать оставленное») возвращает в модуль, согласие показывает экран «Забег завершён» с текстом финала и итогами. «В главное меню» → кнопки «Продолжить» больше нет.
22. **Журнал** (кнопка HUD): вкладка «Хроника» — записи забега сверху вниз от свежих к старым, у каждой остаток O2; вкладка «Архив» — найденные лор-фрагменты. В бою и на экране смерти кнопка неактивна.
23. **Настройки** (кнопка HUD): переключить размер шрифта — интерфейс сразу перерисовывается крупнее/мельче, после перезапуска игры размер сохраняется. Выключить «Анимации» — переходы между экранами становятся мгновенными. «Звук: выключен» скрывает громкость и глушит всё; при включении и смене громкости сразу звучит образец, выбор сохраняется между запусками.
24. **Звук** (на слух): кнопки щёлкают; вход в модуль — дверь, лифт — гидравлика, «Карта» — шелест карты; находки, лечение, баллон, ключ, запертый узел, запись в архиве, крафт и надевание звучат каждый своим звуком; в бою выстрел, удар, промах и попадание по игроку идут в ритме эффектов, «Победа» — короткий аккорд; кислород ниже 60 — один сигнал тревоги; экраны смерти и победы — свои мелодии.
25. Кнопка **Карта** открывает карту поверх модуля (маршрут, выход из модуля — только при «Идти»), в ситуации — карту только для просмотра с «✖ Закрыть карту».

## Соглашения по коду

- **GDScript:** отступы табами, `snake_case`, типизация там, где тип очевиден. Приватные методы и поля начинаются с `_`. Doc-комментарии (`##`) пишутся в начале файла и описывают ответственность системы.
- **Язык:** комментарии, сообщения `push_warning`/`push_error` и тексты UI — на русском. Сообщения начинаются с имени системы: `"MapSystem: ..."`.
- **Экраны переключает только `GameState`.** Системы эмитят сигналы или вызывают методы `GameState` (`enter_location`, `enter_situation`, `start_location_event`, `leave_location`).
- **UI не хранит игровое состояние.** Интерфейс строится из кода (без `.tscn`-разметки) и полностью перерисовывается: `Game.gd` — по `screen_changed`, `CharacterPanel` — после каждого действия. Новые экраны используют хелперы `scenes/ui/UiKit.gd` через `preload` (без `class_name`, чтобы скрипты работали в headless-прогоне без пересборки кэша классов).
- **Методы действий возвращают текст ошибки** (`CharacterSystem.equip`, `unequip`, `CraftingSystem.craft`): `""` — успех, иначе — сообщение для игрока.
- **Контент — только в `data/`.** Никаких захардкоженных id локаций, ситуаций и предметов в коде, кроме дефолтов-фоллбеков.
- **Файлы `.uid` коммитятся** рядом со скриптами (Godot создаёт их при сканировании в редакторе). `.godot/`, `artifacts/`, `export_presets.cfg` в `.gitignore`.

## Типовые изменения

### Новый тип эффекта или условия

1. Добавить ветку `match` в `autoload/EffectResolver.gd` (`apply_effect` или `check_requirement`).
2. Добавить проверку ссылок в `tools/validate_content.py` (`check_effects` или `check_requires`); иначе валидатор выдаст «неизвестный тип».
3. Для условий, которые встречаются в рецептах, — текст в `WorkbenchPanel._describe_requirement()`.
4. Описать тип в таблице в [CONTENT.md](CONTENT.md).

### Новая характеристика

1. Ключ и название — в `CharacterSystem.STAT_TITLES`. Для процентных значений — ещё и в `PERCENT_STATS`.
2. Ключ — в `STATS` в `tools/validate_content.py`.
3. Применение — там, где она работает (например, в `CombatSystem`).
4. Описание — в таблице «Характеристики» в [CONTENT.md](CONTENT.md).

### Новый слот снаряжения

1. `CharacterSystem.SLOTS` и `SLOT_TITLES`.
2. `EQUIP_SLOTS` в валидаторе.
3. Позиция кнопки и точка на фигуре в `CharacterDollView.LAYOUT`, отрисовка части тела в `_draw()`.

### Новый тип спецдействия в бою

1. Ветка в `CombatSystem._resolve_special()`.
2. Разрешённый тип в `validate_content.py` (проверка `special_actions`).
3. Описание в [CONTENT.md](CONTENT.md).

### Новый манёвр в бою или новый тип ИИ противника

1. Манёвр: подпись в `CombatSystem.MOVE_TITLES`, доступность — в `get_available_moves()`, разрешение — в `_resolve_player_move()`.
2. Тип ИИ: ветка в `CombatSystem._choose_enemy_move()`, значение в `ENEMY_AI_TYPES` валидатора.
3. Описание — в таблицах «Бой» в [ARCHITECTURE.md](ARCHITECTURE.md) и «Враги» в [CONTENT.md](CONTENT.md).

### Новая иллюстрация или иконка

1. Функция-рисовалка в `tools/make_pixel_art.py` и запись в список сцен/иконок.
2. `python tools/make_pixel_art.py`, затем импорт: `Godot --headless --path . --import`.
3. Сцену подключить полем `image` в контенте; иконка предмета подхватывается по его id автоматически.

### Новый звук

1. Строка `id → (файл библиотеки, целевой RMS)` в `SOUNDS` у `tools/import_sounds.py`, затем скрипт и импорт Godot.
2. id — в `SoundSystem.SOUNDS`; вызов — по сигналу системы в `SoundSystem._ready()` или `SoundSystem.play(id)` из UI.
3. Строка в таблице «Звук» в [ARCHITECTURE.md](ARCHITECTURE.md).

### Новая система с состоянием забега

1. Реализовать `reset_for_new_run()`, `to_save_data()`, `load_save_data()`.
2. Зарегистрировать в `project.godot` → `[autoload]`, соблюдая порядок: зависимости выше, `GameState` последним.
3. Подключить в `SaveManager`: `start_new_run()`, `save_run()`, `load_run()` (или `save_meta()`/`load_meta()` для meta-слоя), с учётом порядка загрузки.

### Новый экран

1. Значение в конце `GameState.Screen` (порядковые номера используются в логах и тестах).
2. Переходы — только методами `GameState`.
3. Ветка в `Game._render_current_screen()` и функция `_render_<screen>()`.

### Подсказка (tooltip) на элементе UI

Отдельной системы тултипов в проекте нет — используется нативное поле `Control.tooltip_text` (Godot показывает его сам при наведении мыши, с задержкой). Сейчас применяется только в `scenes/ui/SectorMapView.gd`: кнопки палуб (`_floor_tooltip`) и узлы карты (`_node_tooltip`) собирают текст построчно (`"\n".join(lines)`) из полей узла/палубы, описанных в [CONTENT.md](CONTENT.md#узел) (`title`, `note`, `sealed`, `target_floor`), и статуса узла. Неразведанный отсек показывает только «Неизвестный отсек» и палубу.

Как добавить тултип новому элементу:

1. После создания `Control`/`Button` присвоить `.tooltip_text` строкой. Для составного текста — свою функцию `_xxx_tooltip(data) -> String` рядом с остальной отрисовкой, по образцу `SectorMapView`.
2. Текст — на русском, короткими строками (заголовок, затем факты), без хардкода: брать только поля из `data/`, а не константы в коде.
3. Если для тултипа нужно новое поле контента — задокументировать его в [CONTENT.md](CONTENT.md).
4. Хелпера для тултипов в `UiKit.gd` нет. Если понадобится не просто текст (кастомная панель, иконка, своя задержка) — переопределять `Control._make_custom_tooltip()` и добавлять хелпер в `UiKit`, а не городить решение на месте.

Особенности и ограничения:

- **Тултип не покажется на телефоне.** `tooltip_text` всплывает по наведению мыши; на тач-экране нет состояния «навёл, но не нажал», поэтому в реальной игре (Android/iOS) это фактически недоступно игроку. Годится как приём для отладки (мышь в редакторе, клики через MCP), но не как способ донести обязательную информацию — её нужно выводить видимым текстом (как это делает `CharacterPanel`).
- **`_node_tooltip()` не учитывает `reveal_title_when_locked`.** Для видимого запертого узла (статус `door`) тултип показывает `title` и `note`, хотя подпись под иконкой при `reveal_title_when_locked: false` заменяется на «Неизвестно» (`_node_label()`). Если узел должен быть загадкой до открытия — не класть в `note` спойлерный текст, либо сначала поправить `_node_tooltip()`, чтобы он тоже проверял `reveal_title_when_locked`.

## Экспорт под Android

В репозитории лежит пресет `export_presets.cfg` (preset `Android`): пакет `com.cosmotext.game`, `arm64-v8a`, minSdk 24, immersive mode, без разрешения `INTERNET`. Иконки — `assets/icon*.png`. Сборки, ключи и `*.apk` в `.gitignore`.

**Ориентацию APK задаёт только `project.godot` → `display/window/handheld/orientation`.** В Godot 4 это enum `DisplayServer.ScreenOrientation` (`1` — portrait), а не строка, как в Godot 3: строковое значение приводится к `0` и APK собирается ландшафтным. У пресета Android в Godot 4 ключа `screen/orientation` нет, он игнорируется. Проверка — в `tools/build_android.sh`: `aapt dump xmltree` должен показать `android:screenOrientation=(type 0x10)0x1`.

### Тулчейн

Весь тулчейн вынесен с системного диска в `D:\Repos\CosmoToolchain` (~2,7 ГБ):

| Компонент | Версия | Путь |
|---|---|---|
| Godot export templates | 4.7.2.stable | `D:\Repos\CosmoToolchain\godot-export-templates\4.7.2.stable` |
| JDK | Temurin 17.0.20.1 | `D:\Repos\CosmoToolchain\jdk\jdk-17.0.20.1+1` |
| Android SDK | `platform-tools`, `build-tools;34.0.0`, `platforms;android-34` | `D:\Repos\CosmoToolchain\android-sdk` |
| debug.keystore | создан `keytool` | `D:\Repos\CosmoToolchain\keystores\debug.keystore` (пароль `android`, алиас `androiddebugkey`) |

Пути к JDK, SDK и debug-ключу Godot берёт из настроек редактора (`%APPDATA%\Godot\editor_settings-4.7.tres`): `export/android/java_sdk_path`, `export/android/android_sdk_path`, `export/android/debug_keystore`.

**Шаблоны экспорта** Godot ищет строго в своём каталоге данных, настройки для них нет. Поэтому `%APPDATA%\Godot\export_templates` — это junction (symlink каталога) на `D:\Repos\CosmoToolchain\godot-export-templates`; места на C: он не занимает. Пересоздать после переустановки Godot:

```powershell
New-Item -ItemType Junction -Path "$env:APPDATA\Godot\export_templates" -Target "D:\Repos\CosmoToolchain\godot-export-templates"
```

### Сборка

```bash
tools/build_android.sh            # debug APK → build/CosmoTextGame.apk
tools/build_android.sh release    # release APK → build/CosmoTextGame-release.apk
```

Скрипт сначала гоняет валидатор контента, затем вызывает Godot в headless и проверяет подпись через `apksigner`. Пути тулчейна берутся из `D:\Repos\CosmoToolchain` и переопределяются переменными `TOOLCHAIN`, `JAVA_HOME`, `ANDROID_SDK`, `GODOT`. Для release нужен ключ через переменные окружения `GODOT_ANDROID_KEYSTORE_RELEASE_PATH`, `_USER`, `_PASSWORD` (Godot читает их сам).

Установка на устройство: `D:\Repos\CosmoToolchain\android-sdk\platform-tools\adb.exe install -r build\CosmoTextGame.apk`. Логи запущенной игры: `adb logcat -s godot`.

### Что различается между debug и release

- **MCP-мост.** `mcp_bridge_game.gd` поднимает TCP-порт 9501 только при `OS.is_debug_build()`. В release-сборке автозагрузка выходит из `_ready()` сразу и не слушает порт. Редакторный плагин `addons/mcp_bridge` в APK не попадает.
- **Экономика.** В обеих сборках пока работает `MockEconomyProvider` (покупка и реклама всегда успешны). Перед публикацией заменить на реального наследника `EconomyProvider` в `EconomyManager._provider`.
- **Подпись.** debug подписывается debug-ключом Godot, release — ключом из переменных окружения. Ключ публикации в репозиторий не кладём.

### Проверено

APK 0.1.0 собирается из чистого состояния: debug 28,4 МБ и release 26,6 МБ, оба проходят `apksigner verify` (схемы v2 и v3), `aapt2 dump badging` показывает `com.cosmotext.game`, minSdk 24, `arm64-v8a`, `aapt dump xmltree` — `screenOrientation=0x1` (portrait). На реальном устройстве игра ещё не запускалась — нужен телефон с включённой отладкой по USB или эмулятор.
