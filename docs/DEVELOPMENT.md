# Разработка

## Окружение

| Что | Версия | Зачем |
|---|---|---|
| Godot | 4.7 (проверялось на 4.7.2), стандартная сборка без .NET | Движок, редактор, запуск, смоук-тест |
| Python | 3.10+ | `tools/validate_content.py` (только стандартная библиотека) |
| uv | любая свежая | Только для MCP-сервера (см. [MCP.md](MCP.md)) |

## Запуск

1. Godot → Import → выбрать `project.godot`.
2. **F5** — главная сцена `scenes/Game.tscn`.
3. Параметры окна: вьюпорт 1080×1920, портретная ориентация, `stretch/mode = canvas_items`, рендерер Mobile.

Если окно не помещается на монитор, уменьшите его в *Project Settings → Display → Window → Size → Window Width/Height Override* (например 540×960). Не коммитьте это изменение, если оно нужно только вам.

## Проверки

### Контент

```bash
python tools/validate_content.py
```

Если в консоли Windows выводятся кракозябры или падает `UnicodeEncodeError`, запустите так:

```bash
PYTHONIOENCODING=utf-8 python tools/validate_content.py
```

### Смоук-тест логики

`scenes/Main.tscn` проходит вертикальный срез через системы без UI и проверяет:
- **модули и события:** автособытия и цепочку по `event_done`, ручные разовые и повторяемые события, лифт, отступление и повторную встречу с дроном, бой с победой и `on_win`, открытие шлюза, возврат в пройденный модуль;
- **персонаж:** стартовое снаряжение, взаимодействие с предметом, запрет выбросить сюжетный предмет, надевание и снятие, бонусы брони, урона, слотов, побега и HP, `has_item` по надетому, изучение навыка, крафт с условием по навыку;
- **сохранение и загрузку** всего перечисленного.

В редакторе: открыть `Main.tscn` и нажать **F6**. Из консоли — через консольную сборку Godot (`*_console.exe`):

```bash
Godot_v4.7.2-stable_win64_console.exe --headless --path . res://scenes/Main.tscn
```

В конце выводится `SMOKE OK` (код выхода 0) или `SMOKE FAIL` со списком упавших проверок (код 1).

Тест **перезаписывает `run.json` и `checkpoint.json`** в `user://`; сохраните их, если нужны. Строка `MCP Bridge Game: Failed to listen on port 9501` при прогоне нормальна, если параллельно запущена игра.

При изменении контента вертикального среза (`hub`, `cargo_bay`, `alien_shuttle`, `sit_1_*`, предметы, навыки, рецепты из среза) обновляйте проверки в `scenes/Main.gd`.

## Content Studio — встроенный редактор контента

Проект содержит Godot EditorPlugin `CosmoText Content Studio`. После открытия проекта он появляется в правом доке редактора. Если док скрыт: **Editor → Docks → CosmoText Content Studio**.

Редактор работает с теми же файлами, что и игра:

- **Карта** — сектор, палубы, отсеки, состояния, координаты сетки и связи;
- **Локации** — описание и события;
- **Ситуации** — текст, варианты выбора, условия и эффекты;
- **Предметы** — имя, категория, слоты, описание, использование и взаимодействия;
- **Крафты** — результат, ингредиенты и условия;
- **Журнал** — заголовок и текст заметки.

Порядок работы:

1. Выбрать раздел и ресурс.
2. Изменить поля или добавить отсек/событие/вариант.
3. Нажать **Сохранить**.
4. Нажать **Проверить весь контент** и отдельно запускать `python tools/validate_content.py` перед коммитом.

Редактор сохраняет JSON автоматически форматированным и запускает пересканирование файлов Godot. Условия, эффекты и ингредиенты редактируются строками с типом и параметрами; расширенные поля (например особые взаимодействия предметов и параметры карты) остаются отдельными JSON-полями, чтобы не потерять возможности схемы.

## Сохранения

Путь: `%APPDATA%\Godot\app_userdata\CosmoTextGame\` (в редакторе: *Project → Open User Data Folder*).

| Файл | Что внутри |
|---|---|
| `run.json` | Текущий забег: ресурсы, сумка, снаряжение и навыки, модули и события, карта |
| `checkpoint.json` | Точка отката |
| `meta.json` | Архив лора и экономика, переживают смерть |
| `logs/` | Логи запусков игры |

Когда какой файл пишется, описано в [ARCHITECTURE.md](ARCHITECTURE.md#сохранения).

**Сбросить прогресс** — удалить `run.json`, `checkpoint.json` и `meta.json`. Удаление `meta.json` сбрасывает архив и счётчик рекламных откатов.

## Ручная проверка вертикального среза

После изменений в UI пройдите сценарий целиком (логику без UI покрывает смоук-тест):

1. Меню → **Новая игра** → автособытие «пробуждение» (`sit_1_1_capsule`). Выбрать опцию и проверить HUD (`HP: x/100`).
2. Сразу второе автособытие (`sit_1_2_wreckage`) → «Взять планшет, не читать — потом».
3. Экран модуля «Капсула»: описание, действие «Осмотреть капсулу» (повторяемое), «Выйти на карту».
4. **Персонаж → Предметы:** у планшета кнопка «Прочитать записи» → сообщение, запись в «Архиве», кнопка исчезла. Кнопки «Выбросить» у планшета нет.
5. **Персонаж → Снаряжение:** на кукле «Тело — Лётный комбинезон», остальные слоты «пусто». Клик по слотам меняет подсветку; характеристики «Броня: +1».
6. Карта → лифт → палуба 02 → «Грузовой» → дрон. «Отступить» → узел `!`. Снова войти → «Войти и вступить в бой» → спецдействие с планшетом → победа. Игрок в модуле, узел `✓`.
7. «Обыскать контейнеры» → сумка 6/6.
8. **Персонаж → Предметы:** надеть «Обломок трубы». В слоте «Руки» — труба, «Урон в ближнем бою: +6».
9. **Персонаж → Крафт:** «Жилет из обшивки» подсвечен как недоступный (нужна Инженерия). Создать «Самодельный рюкзак» → надеть его → «Сумка: …/9».
10. **Персонаж → Навыки:** очков 2 → изучить «Инженерию». **Крафт:** создать жилет → надеть: комбинезон ушёл в сумку, «Броня: +3».
11. Закрыть экран персонажа → «Вскрыть шлюз к шаттлу» доступно (труба надета). Шаттл → «Обыскать кабину» → надеть ботинки.
12. В бою (новый забег или другой враг) подсказка у «Атаковать» показывает оружие; кнопка «Персонаж» неактивна.
13. Лифт на палубу 01 → «Капсула» (чекпойнт). Перезапустить игру → **Продолжить** → снаряжение и навыки на месте.
14. Намеренно умереть → экран смерти. Проверить «Вернуться к чекпойнту» и «Начать заново».

## Соглашения по коду

- **GDScript:** отступы табами, `snake_case`, типизация там, где тип очевиден. Приватные методы и поля начинаются с `_`. Doc-комментарии (`##`) пишутся в начале файла и описывают ответственность системы.
- **Язык:** комментарии, сообщения `push_warning`/`push_error` и тексты UI — на русском. Сообщения начинаются с имени системы: `"MapSystem: ..."`.
- **Экраны переключает только `GameState`.** Системы эмитят сигналы или вызывают методы `GameState` (`enter_location`, `enter_situation`, `start_location_event`, `leave_location`).
- **UI не хранит игровое состояние.** Интерфейс строится из кода (без `.tscn`-разметки) и полностью перерисовывается: `Game.gd` — по `screen_changed`, `CharacterPanel` — после каждого действия. Новые экраны используют хелперы `scenes/ui/UiKit.gd` через `preload` (без `class_name`, чтобы скрипты работали в headless-прогоне без пересборки кэша классов).
- **Методы действий возвращают текст ошибки** (`CharacterSystem.equip`, `unequip`, `CraftingSystem.craft`): `""` — успех, иначе — сообщение для игрока.
- **Контент — только в `data/`.** Никаких захардкоженных id локаций, ситуаций и предметов в коде, кроме дефолтов-фоллбеков.
- **Файлы `.uid` коммитятся** рядом со скриптами (Godot создаёт их при сканировании в редакторе). `.godot/`, `artifacts/`, `export_presets.cfg` в `.gitignore`.

## Типовые изменения

### Новый тип эффекта или условия

1. Добавить ветку `match` в `autoload/EffectResolver.gd` (`apply_effect` или `check_requirement`).
2. Добавить проверку ссылок в `tools/validate_content.py` (`check_effects` или `check_requires`); иначе валидатор выдаст «неизвестный тип».
3. Для условий, которые встречаются в рецептах, — текст в `CharacterPanel._describe_requirement()`.
4. Описать тип в таблице в [CONTENT.md](CONTENT.md).

### Новая характеристика

1. Ключ и название — в `CharacterSystem.STAT_TITLES`. Для процентных значений — ещё и в `PERCENT_STATS`.
2. Ключ — в `STATS` в `tools/validate_content.py`.
3. Применение — там, где она работает (например, в `CombatSystem`).
4. Описание — в таблице «Характеристики» в [CONTENT.md](CONTENT.md).

### Новый слот снаряжения

1. `CharacterSystem.SLOTS` и `SLOT_TITLES`.
2. `EQUIP_SLOTS` в валидаторе.
3. Позиция кнопки и точка на фигуре в `CharacterDollView.LAYOUT`, отрисовка части тела в `_draw()`.

### Новый тип спецдействия в бою

1. Ветка в `CombatSystem._resolve_special()`.
2. Разрешённый тип в `validate_content.py` (проверка `special_actions`).
3. Описание в [CONTENT.md](CONTENT.md).

### Новая система с состоянием забега

1. Реализовать `reset_for_new_run()`, `to_save_data()`, `load_save_data()`.
2. Зарегистрировать в `project.godot` → `[autoload]`, соблюдая порядок: зависимости выше, `GameState` последним.
3. Подключить в `SaveManager`: `start_new_run()`, `save_run()`, `load_run()` (или `save_meta()`/`load_meta()` для meta-слоя), с учётом порядка загрузки.

### Новый экран

1. Значение в конце `GameState.Screen` (порядковые номера используются в логах и тестах).
2. Переходы — только методами `GameState`.
3. Ветка в `Game._render_current_screen()` и функция `_render_<screen>()`.

## Экспорт

Пресетов экспорта в репозитории нет (`export_presets.cfg` в `.gitignore`). Перед сборкой под Android или iOS:

- **Убрать автозагрузку `McpBridgeGame`** (или обернуть её в `if OS.is_debug_build()`). Она открывает TCP-порт 9501 и позволяет кликать и снимать скриншоты извне. Плагин `addons/mcp_bridge` — редакторный (`EditorPlugin`) и в сборку не попадает.
- Заменить `MockEconomyProvider` на реальный провайдер в `EconomyManager._provider`.

## Известные проблемы

| # | Проблема | Где |
|---|---|---|
| 1 | `meta.json` пишется только при смерти, рестарте или откате. Открытый лор и покупка полного доступа теряются, если закрыть игру, не умерев | `SaveManager` |
| 2 | `run.json` пишется только при чекпойнте (экран хаба или `next: "map:..."`). «Продолжить» не восстанавливает прогресс после последнего визита в хаб, в том числе крафт и смену снаряжения | `SaveManager` |
| 3 | Откат через рекламу выполняется даже при неуспехе рекламы: результат `watch_rollback_ad()` не проверяется. С mock-провайдером не проявляется | `Game._death_rollback()` |
| 4 | `requires` верхнего уровня у ситуации не применяется движком | `SituationEngine` |
| 5 | У закрытых узлов `copilot_body` и `reactor` ещё нет локаций (валидатор предупреждает) | `data/sectors/wreck_01.json` |
| 6 | Стартовых патронов и их источников нет, поэтому навык «Стрельба» и `ranged_damage` пока ни на что не влияют; нет предметов для слота «Шлем» | контент |
| 7 | Эффект `item_remove`, уничтожающий надетый рюкзак, может оставить сумку переполненной (новые предметы не добавятся, пока не освободится место) | `CharacterSystem.remove_equipped()` |
| 8 | Нет UI покупки полного доступа | `Game.gd` |
| 9 | Сигнал `full_access_changed` объявлен и в `EventBus`, и в `EconomyManager` (эмитятся оба) | `EconomyManager` |
